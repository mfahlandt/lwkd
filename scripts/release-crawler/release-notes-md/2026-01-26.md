### 🚀 Keep Your Scaffold Updated

🎉 Our migration guide was fully updated to help you upgrade from `any` version to the `latest`. It also now includes AI migration helpers/commands to guide upgrades for old scaffolds where manual steps are required. See the [migrations guidance](https://book.kubebuilder.io/migrations.html).

> _Automate updates with [`kubebuilder edit --plugins="autoupdate.kubebuilder.io/v1-alpha"`](https://book.kubebuilder.io/plugins/available/autoupdate-v1-alpha) or run them manually with [`kubebuilder alpha update`](https://book.kubebuilder.io/reference/commands/alpha_update). If your `PROJECT` file does **not** include `cliVersion`, you may need a one-time upgrade, and [`kubebuilder alpha generate`](https://book.kubebuilder.io/reference/commands/alpha_generate.html) can fully re-scaffold the project in one step. After that, updates work seamlessly. ([More info](https://master.book.kubebuilder.io/migrations.html))_


## ⚠️ Breaking changes

### controller-runtime` v0.23.0` upgrade (`v0.22.4` → `v0.23.0`)

This release updates Kubebuilder scaffolding to match controller-runtime v0.23.0. This version includes breaking changes that impact generated projects:

1. **Type-safe webhook builder API** — webhooks now use generics for stronger type safety
2. **New Events API** — migration from `tools/record` to `tools/events`
3. **ENVTEST teardown** — `testEnv.Stop()` now requires an `Eventually` wrapper for graceful shutdown

- For manual upgrade steps for older projects, see: https://github.com/kubernetes-sigs/kubebuilder/pull/5378
- For the full upstream change list, see controller-runtime v0.23.0 release notes: https://github.com/kubernetes-sigs/controller-runtime/releases/tag/v0.23.0

### If you use the Helm plugin to distribute your project

This release includes major Helm plugin changes (community-raised fixes and improvements have been addressed). Please update your project:

- **If you use [helm/v1-alpha](https://book.kubebuilder.io/plugins/available/helm-v1-alpha)**: upgrade to **[helm/v2-alpha](https://book.kubebuilder.io/plugins/available/helm-v2-alpha)**. Using [kubebuilder alpha generate](https://book.kubebuilder.io/reference/commands/alpha_generate) or [kubebuilder alpha update](https://book.kubebuilder.io/reference/commands/alpha_update) will re-scaffold your project and auto-migrate Helm v1 → v2.

- **If you use helm/v2-alpha and you update manually** (not via [kubebuilder alpha generate](https://book.kubebuilder.io/reference/commands/alpha_generate) / [kubebuilder alpha update](https://book.kubebuilder.io/reference/commands/alpha_update), or neither has the [AutoUpdate Plugin](https://book.kubebuilder.io/plugins/available/autoupdate-v1-alpha) configured), then re-generate the chart with all fixes:

```shell
kubebuilder edit --plugins=helm/v2-alpha --force
```
  If you have customisations, back up your current Helm chart first so you can re-apply them on top of the latest version.

**Tip:** Check the `PROJECT` file to see which plugin/version your project is using.
